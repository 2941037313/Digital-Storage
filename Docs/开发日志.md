### 建造材料 patch 兼容重构(用户拍板 B2)
根因:`WorkGiver_DS_WithdrawForConstruct` 复刻原版材料判定时漏掉 `Blueprint_Install` 分支,对安装蓝图调用 `TotalMaterialCost()` → 原版主动 `Log.Error` 刷屏。当前 `if (c is Blueprint_Install) return null` 只是止血;真正的兼容问题是 DS 用独立高优先级 WorkGiver + ProcessInput Prefix 替换原版流程,绕过了原版/第三方 gate。

- **投递侧** — 抽出 `DSConstructionDelivery` 共享 helper;`ConstructLedgerPlanner.TryPlan` 增加 `pawn`/`forced` 参数,数量语义对齐原版 `ResourceDeliverJobFor`(`forced ? ThingCountNeeded : GetSpaceRemainingWithEnroute(def, pawn)`);安装蓝图 + 第三方 `IConstructible` 异常双重防护。
  - 保留 `WorkGiver_DS_WithdrawForConstruct`(Hauling priority 200,账本优先,现有体验不变)。
  - 新增 `Patch_ResourceDeliverJobFor` Postfix:原版 `ResourceDeliverJobFor` 返回 null 时用账本补 `DigitalStorage_WithdrawToConstruction`;尊重 `__runOriginal`,Priority=Low。Achtung 强制建造 / Construction work / VEF 子类等原版路径由此覆盖。
- **菜单侧** — `Patch_DesignatorBuild_ProcessInput` 改为 Transpiler:在 `List<Thing>.get_Count` 前插入账本可用性判断,保留原版 `writeStuff`/`sourcePrecept`/`onCloseCallback`/`CheckCanInteract`,与其他 `ProcessInput` Transpiler(VMF / Storage Network / MultiFloors)链式共存;Transpiler 匹配失败时降级到低优先级 Prefix(VEF/角色 mod 的 `JobOnThing` gate 由 Postfix 路径天然继承)。
- **兼容决策**:
  - MultiFloors 跨层建造单列 issue(用户后续单独做多层 mod)。
  - Infinite Storage 等 Prefix 整体替换菜单的 mod:接受已知限制,不做兼容。

### RAG 代码审查 + 3.0 工坊反馈修复(fix/review-2026-09-11 分支)
用 RAG 把 66 个源文件全量读了一遍,可疑 API 全部回查原版 `Assembly-CSharp` 求证;同时收到 3.0 工坊的 11 条反馈,逐条定位到代码。

- **食物方案绕过(真 bug)** — `ConsumptionHelper.TryCreateJob` 只按 `IsNutritionGivingIngestible` 选料,没有走原版 `JobGiver_GetFood` 的 `FoodUtility.WillEat`(FoodIsSuitable + FoodPolicy.Allows + 泰特托 + 圣兽肉 + 头衔)。补上同口径 gate + `IsDrug` 的 `DrugIsSuitable`。对应反馈「禁止吃虫胶无效」。
- **凭空制作(真 bug)** — `LedgerBillPlanner.TryPlan` 只查 `Available` 不占预订,WorkGiver 判定到 JobDriver 执行之间材料可能被别人吃掉;且 `Notify_Starting` 与 `ReservePlanInLedger` 两次预订的时序与旧 plan 脱节。改为 `ReservePlanInLedger` 里「先 `ReleaseByJob` → 此刻重算 plan → 预留 → 用新 plan 覆盖」,执行期的 plan 必然可提取。对应「培育器材料不够也能做」。
- **消费 job 补预订** — `JobDriver_DS_Consume.Notify_Starting` 按 plan 在账本上锁住,拿不到就放弃(原来白跑一趟)。
- **建筑进核心(真 bug)** — `LedgerPolicy.CanIngest` 排除 `category == Building` 与 `building.IsDeconstructible`。对应「壁灯等建筑被搬进核心且取不出来」。
- **交易后清仓(真 bug)** — `RecordSoldForAnyActiveDialog` / `CleanupAfterDealForAnyActiveDialog` 旧实现只处理第一个 state(`return`),多窗口/DTI 换窗时其余条目被遗弃(账本已扣、物品已没)。改为遍历全部。

### Biotech 机械培育器适配(排查)
机械师培育 job 链路考古:`DoBillsMechGestator`(Biotech WorkGivers.xml,workType=**Smithing**、priority 210)发 DoBill job;配方是**固定原料**(钢×50+副核心×1),不消耗营养;原料必须进 `Building_WorkTableAutonomous.innerContainer`(原版 CollectIngredientsToils 的 placeInBillGiver=true → DepositHauledThingInContainer),培育完成时 `ClearAndDestroyContents` 才消耗。

- **修复:原料进培育器容器** — `JobDriver_DS_WithdrawForBill.WithdrawAndPlaceAllToil`:billGiver 是 `Building_WorkTableAutonomous` 时,取出原料直接 `innerContainer.TryAdd` + `Notify_HauledTo` + `UpdateJobWithPlacedThings`,失败退回账本。原实现放地上 → 原料永不消耗(凭空多料)+ 培育器 UI 显示 0/50
- **修复:状态检查防重复取料** — `WorkGiver_DS_WithdrawForBill.JobOnThing`:`Bill_Autonomous.State != Gathering`(Preparing 续周期 / Formed 取成品)时跳过,交回原版 WorkOnFormedBill

### 右键"缺少材料"链路调研
`FloatMenuMakerMap` → `FloatMenuOptionProvider_WorkGivers.GetWorkGiverOption`(JobFailReason.Clear → ShouldSkip(forced) → JobOnThing(forced),job==null 且有 reason 才显示"不能做: 缺少材料")→ `WorkGiver_DoBill.StartOrResumeBillJob`(flag=makingFor,missingIngredients 只在右键时收集)。结论:mod WorkGiver(priority 999)先于原版取料,账本不足时原版"缺少材料"兜底,链路完整。
