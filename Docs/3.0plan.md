# 数字存储 3.0 开发计划

**版本**：v3.0 设计文档（首版）
**起稿日期**：2026-05-12
**基准存档**：git tag v2.5 / v2.53（阶段 3 收尾）
**当前状态**：阶段 1 / 2 / 3 已完成；阶段 4.1（进核心派工）已完成，处于可编译的过渡态

---

## 一、设计哲学（一句话）

**核心内部没有物品，只有账本；原版派工看不到账本；我们自己派工直接操作账本。**

任何涉及"把核心里的东西呈现给原版系统"的代码都是 2.0 的技术债。v3 不伪造、不传送、不擦屁股。

---

## 二、v2.0 问题诊断

三大痛点（物流低效 / 虚拟 / 预留复杂）其实是同一个病根的三个症状：**原版 haul/ingredient 系统只认"有坐标的真实 Thing"**。v2.0 为了让原版认可虚拟库存，只能反向往坐标上伪造 Thing，导致：

- 任何读取物品坐标/重量/堆叠/财富/绘制的原版函数都要补丁兜底；
- "仅作位置提供者的预留物品"这种怪字段；
- 瞬移补丁掩盖"pawn 要真的走到核心去拿"；
- 芯片分支散落在每个补丁里，行为不一致。

v3 的破解：**不让原版派工系统去核心找材料**。我们自己写一套派工，它从一开始就知道"核心里的东西不在地图上"，不问坐标。

---

## 三、坐标问题（v3 最关键的决策）

**原版规矩**：游戏要派活，材料必须有坐标。

**v3 答案**：
- **输入接口就是坐标**。核心的"坐标"是所有接口的坐标之一。
- **核心本身也是接口**，没接口时核心格子当代理点用。
- **pawn 寻路去最近的接口（或核心）**。接口是真实建筑，真实坐标，原版寻路照用。
- **核心内部不需要坐标**——账本只有"钢 × 2300"这样的数字。
- **芯片 pawn 连接口都不用去**，脑子里就是接口，原地伸手。

## 四、架构分层

```
┌─────────────────────────────────────────────────┐
│  建筑层：核心 / 输入接口 / 升级组件 / 芯片          │
│  （纯物理实体，不做库存逻辑）                     │
├─────────────────────────────────────────────────┤
│  账本层：核心的库存表 + 预订表                    │
│  （纯数据，无 Thing 实例，存档只占几 KB）          │
├─────────────────────────────────────────────────┤
│  派工层：我们自己的派工器和工单                   │
│  （跳过原版派工，直接对账本读写）                 │
├─────────────────────────────────────────────────┤
│  接入层：贸易 / 商队 / 右键菜单 / UI 面板          │
│  （旁路接入账本，不经过原版存储）                 │
└─────────────────────────────────────────────────┘
```

**关键隔离**：账本层对外只暴露四件事——问、取、存、预订/释放。上层爱怎么用怎么用，账本本身不管谁在用。

---

## 五、账本层（核心数据结构）

### 三张表

- **库存表**：`Dictionary<ItemKey, long>`，key 按材质/品质/健康度等一切会影响"是哪种东西"的维度分组。
- **预订表**：`Dictionary<Job, List<(ItemKey, int count)>>`，每张工单预订了哪几种物品、各几个。
- **元信息**：容量（升级等级决定）、网络名。

### 对外四个动作

| 动作 | 语义 | 并发约束 |
|------|------|----------|
| **可用量** | 库存 - 预订 = 可用 | 纯读 |
| **存入** | 把 pawn 手上这个 Thing 吃进去 | 一帧完成，Thing 销毁 |
| **取出** | 给我 N 个 X，**在 pawn 手里直接生成 N 个 X**（不经过地图） | 一帧完成 |
| **预订/释放** | 工单开始预订、工单结束自动释放 | 只暴露"按 Job 预订/释放"，不允许单个释放 |

### 容量满了怎么办

存入被拒绝，工单进入"无处可放"状态，按原版 haul 失败路径处理。

### 预订不怕忘了释放的保证

所有预订都绑在 `Job` 对象上。工单有生命周期回调（`JobDriver.Cleanup`），我们在这个**唯一入口**做释放；账本不直接暴露"单个释放"给业务层。

## 六、派工层

### 三个入口覆盖所有情景

**入口 A：物品进核心**
- 扫地图上所有可搬运物品；
- 对每个物品问账本"能吃吗"（白名单 + 容量）；
- 能吃就派"送进核心"工单。
- **优先级高于原版 haul**，核心吃得下就优先进核心，吃不下让原版正常送仓库。

**入口 B：工作台/蓝图要东西出核心**
- 抢在原版派工之前问账本"这些材料凑齐了吗"；
- 凑齐派"从核心取料送到工作台/蓝图"工单；
- 凑不齐让原版继续（去地图找材料，找不到就放弃）。

**入口 C：右键菜单强制取料**
- 玩家右键某个格子 → 菜单列"从核心取 X 放到这里" → 派工单。

### 五种业务场景 → 3 个 JobDriver

观感都是"走到某个点 → 伸手 → 走到另一个点 → 放下"。从 Toil 角度看只有两种**动作方向**——进核心 / 出核心。Bill 场景特殊：要复用原版制作流程（`Toils_Recipe` 硬 cast `JobDriver_DoBill`），所以**单独继承**原版 DoBill，不强行和其他 Withdraw 合并。

**场景到 JobDriver 的映射**：

| 业务场景 | 方向 | JobDriver | 父类 | Job.targetA | Job.targetB（接口） |
|---------|------|-----------|------|-------------|---------------------|
| 物品进核心 | 进 | `JobDriver_DS_Ingest` | JobDriver | 地上物品 | 最近接口/核心 |
| 取料去工作台 | 出 | `JobDriver_DS_WithdrawForBill` | **JobDriver_DoBill** | 工作台 | 最近接口/核心 |
| 取料去蓝图 | 出 | `JobDriver_DS_Withdraw` | JobDriver | 蓝图位置 | 最近接口/核心 |
| 强制取料 | 出 | `JobDriver_DS_Withdraw` | JobDriver | 玩家指定格 | 最近接口/核心 |
| 贸易取料 | 出 | `JobDriver_DS_Withdraw` | JobDriver | 交易船/商队 | 最近接口/核心 |

**统一 Toil 流程**：

```
Ingest（进核心）:
  Reserve targetA（地上物品）
  Goto targetA
  StartCarryThing
  [如无芯片] Goto targetB（接口）
  账本 Ingest，carryTracker 的 Thing 销毁

WithdrawForBill（出核心→工作台）:
  账本 Reserve(job, key, count)  （按 bill 所有材料批量预订）
  [如无芯片] Goto targetB（接口）
  对每种材料：账本 Withdraw → 生成 Thing 塞 carryTracker → 走工作台摆料格 → 放下
  yield 原版 base.MakeNewToils()：制作 / UnfinishedThing / 产出存放全走原版

Withdraw（出核心→其他终点）:
  账本 Reserve(job, key, count)
  [如无芯片] Goto targetB（接口）
  账本 Withdraw → 生成 Thing 塞 carryTracker
  Goto targetA
  对 targetA 做具体动作（放下 / 给蓝图 / 给贸易台）
  AddFinishAction 统一调 account.ReleaseByJob(job)
```

**"终点做什么"** 通过 `Toils_DS.FinalizeByKind(jobKind)` 这个小工厂产出尾段 Toil。加新场景只需：
- 写一个新的 `WorkGiver` 决定什么情况派工；
- 往 `JobKind` enum 加一个值，`FinalizeByKind` 加一个分支；
- **不需要改 JobDriver 本身**。

**芯片捷径实现**：`targetB = LocalTargetInfo.Invalid` 表示"跳过走去接口"。WorkGiver 在派工时判断 pawn 是否有芯片、决定是否填 targetB。JobDriver 对 `targetB.IsValid == false` 直接跳过 Goto 阶段。

**跨地图取料**（all-in 路线）：
- 本地图账本没货时，`JobKind = Withdraw` 的 Job 里 `targetC` 记录远地图核心；
- **pawn 不跨地图移动**，账本扣除在远地图核心账本上发生，物品直接在 pawn 手里生成；
- UI 显示"从 xx 基地取料"。

## 七、接入层

### 贸易

商船/商队的货源列表里，把核心账本内容**以临时列表形式**加进去。成交时：
- 卖出：核心账本扣、商人库存加、银币进玩家口袋；
- 买入：核心账本加、商人库存扣、银币扣。

全程没有任何 Thing 在地上停留。商队离开不需要 pawn 搬货。

### 商队携带

玩家组商队时从核心勾物品带走。实现：点击时从账本扣、在商队临时库存里加等量 Thing。这个 Thing 从此是普通物品，和核心无关。

### UI

- **核心 Inspect 面板**：网络名、已用/总容量、分类统计。
- **虚拟库存对话框**：每种物品可用数量（扣除预订后）、搜索、排序、一键取出。
- **右键菜单强制取料对话框**：输入数量。
- **ITab（核心建筑上）**：同虚拟库存对话框。

UI 不直接读账本表，走账本"问"接口——UI 看到的永远是"你真正能用的"。

## 八、三条重要业务规则（用户拍板）

1. **核心摧毁 → 跨地图转移**（耐久 10 万 + 分帧掉落上限 10 万物品）
   - 先尝试搬到同网络其他地图核心（按剩余容量由多到少排）；
   - 装不下的分帧掉落到核心原位置周围；
   - 上限 10 万条目，超出视为玩家自找麻烦，直接丢弃。

2. **核心自带接口功能**
   - 核心本身交互格也是合法代理点；
   - 接口全没时核心仍可用。

3. **容量全满 → 跟原版一致**
   - 工单失败，物品留原地，pawn 干下一件事。

### 阶段 3：输入接口 ✅ 已完成

- Defs 清理：接口块移除 `ITab_Storage`、`fixedStorageSettings` / `defaultStorageSettings`、`maxItemsInCell`、`preventDeteriorationOnTop`、`ignoreStoredThingsBeauty`、`groupingLabel`；描述改为"走到这里存取"，不再欺骗玩家"放上去自动传送"。

**运行验证标准**（阶段结束由用户在游戏内完成）：

### 阶段 4：派工器和工单（核心环节）

**目标**：**3 个 JobDriver**（Ingest / WithdrawForBill 继承 DoBill / Withdraw）覆盖 5 种业务场景（见第六章），让 pawn 真的动起来。

**文件骨架**：
- `Source/AI/JobKind.cs`：enum（Ingest / WithdrawToBill / WithdrawToBlueprint / WithdrawToSpot / WithdrawForTrade），放在 `Job.debugLabel` 里便于调试。
- `Source/AI/Toils_DS.cs`：共享 Toil 积木（`GotoInterfaceOrSkipIfChip`、`WithdrawFromLedger`、`IngestToLedger`、`FinalizeByKind`）。
- `Source/AI/JobDriver_DS_Ingest.cs`：走到地上物品 → 抬 → 走到接口（芯片跳过）→ 吞账本 → Cleanup 释放预订。
- `Source/AI/JobDriver_DS_Withdraw.cs`：账本 Reserve → 走到接口（芯片跳过）→ 账本 Withdraw 到 carryTracker → 走到 targetA → 按 JobKind 做尾段动作 → Cleanup 释放预订。
- WorkGivers：
  - `WorkGiver_DS_HaulToCore`（优先级高于 `WorkGiver_Haul`）
  - `WorkGiver_DS_WithdrawForBill`（优先级高于 `WorkGiver_DoBill` 的材料查找）
  - `WorkGiver_DS_WithdrawForConstruct`（优先级高于 `WorkGiver_ConstructDeliverResources`）
- `Source/HarmonyPatches/Patch_FloatMenuOption_Withdraw.cs`：右键格子强制取料。

**分步推进**（每步单独验证）：

**4.1** `JobDriver_DS_Ingest` + `WorkGiver_DS_HaulToCore` ✅ 已完成
- 地上钢 → pawn 搬到接口/核心交互格 → 账本 +；芯片 pawn 不去代理点，抬起物品后原地塞进账本。
- `WorkGiverDef` `priorityInType=50`（HaulGeneral 是 15），所以账本能吃的物品抢在原版 haul 前派工。
- `AddFinishAction` 里统一调 `Ledger.ReleaseByJob(job)`——唯一入口，忘不了。
- 账本拒收时（白名单 / 容量爆）工单不派，物品留给原版 haul 去仓库。
- 路上容量变满 → 物品落地按原版失败流程走。

**运行验证**（阶段 4.1 结束由用户在游戏内完成）：
- 放一个核心（带电）+ 接口 → 地图扔一堆钢 → pawn **不**往仓库搬，改搬去接口，到达后钢消失、账本 +。
- 核心断电 → 派工立刻停，地上物品交给原版 haul。
- 非白名单（武器/衣物/尸体/有品质物品）→ 永不派给核心。
- 给 pawn 植入终端芯片 → 搬运时不去接口，抬起物品后**原地**（或走到物品处）就吞进账本。
- 存档 → 读档 → 派工不残留。

**4.2** `JobDriver_DS_WithdrawForBill` + `WorkGiver_DS_WithdrawForBill` ✅ 已完成

### 阶段 4.6：自动消耗接入（I1.5） ✅ 已完成

**目标**：pawn 因饥饿/成瘾/娱乐需要食物/药品/酒而地图找不到时，自动从核心取。

**已产出**：
- 1 个 Harmony Patch 文件（`Patch_ConsumeFromLedger.cs`，3 个 target：`JobGiver_GetFood` / `JobGiver_TakeDrugsForDrugPolicy` / `JoyGiver_Ingest`）+ 1 个 `JobDriver_DS_Consume` + 1 个 `ConsumptionHelper`
- `JobDriver_DS_Consume` 全流程：`DropIncompatibleCarryIfNeeded`（手里异物先放下）→ `WithdrawToCarry`（取料进 carryTracker）→ `CarryToChewSpot`（走到吃的位置）→ `FindAdjacentEatSurface`（找桌子）→ `ChewIngestible` → `FinalizeIngest`。全程复用原版 ingest toils
- `ConsumptionHelper`：`GetIngestAmount` 按饥饿度算所需量（`FoodUtility.StackCountForNutrition`），食物不贪心取满。药/娱乐用 `defaultNumToIngestAtOnce`（通常 1）
- 消费场景**不用预订**——Withdraw 和 Ingest 在同帧完成，无跨帧抢料窗口
- 节流机制：同 tick 同 pawn 刚失败不重试；pawn 已有 ConsumeFromLedger job 不重复创
- `BingeDrug` 暂不覆盖（需要从 `MentalState` 取 chemical 字段，回头补）

**基础层改进**：
- `CoreLedger.Withdraw(key, count, job)` 加可选参数——传 job 时跳过该 job 自己的预订再算可用量 + 取后自动从预订扣，解决 Reserve→Withdraw 自己堵自己的 bug。不传=原版行为，向后兼容

**运行验证**（用户已完成）：

- ✅ 右键取出/搬运/取料全部数量不堵

## 十二、风险清单

1. **原版 ThinkTree 优先级**：我们的 WorkGiver 插在什么优先级？如果被原版抢先派工，pawn 会去地图找材料而不是核心。→ 阶段 4 第一步就要定。
2. **跨地图 Job 存档**：Job 里记 `targetCore` 是个跨 Map 引用。原版对跨 Map Thing 引用的 Scribe 支持有限，可能要用网络名 + 序号重建引用。→ 阶段 5 要早验证。
3. **玩家手动拖动物品进核心的 UI 期望**：v2 里玩家可以把接口当仓库用（放 ShiftClick），v3 改为非 Building_Storage 后会没有这个能力。派工 A 入口能覆盖，但玩家可能期待"拖一下立刻进去"——阶段 3 要测玩家习惯。
4. **Harmony 补丁二次落盘**：v3 定稿后肯定还会有少量补丁（贸易、右键菜单等），不要重新变回 v2 的"补丁泥潭"。写任何新补丁前回来读一次这个文档的第一节。
